### 关键结论（来自 media-mcp 真实提交）
- `61dadf1`：stdio 必须 NDJSON，早期误用 LSP 的 Content-Length 帧格式后整段回退。
- `90a8041`：mimeType 推断必须处理 query string / 大写扩展名。
- `adc58cb`：工具可选参数为空时必须回退到配置默认值，否则下游 400。
- `61480f4`：由 main.go 大 switch 重构为「接口 + 注册表 + init 自注册 + 通用兜底适配器」，main.go 122→69 行。
- 协议层测试用 `os.Pipe` 替换 stdin/stdout，读响应必须 `select` + `time.After` 防挂死。

### 文档中标注的 media-mcp 现存缺陷（勿照抄）
1. `transport.go` 返回本地文件时 `image.data` 用原始字节 `string(fileData)`，MCP 要求 base64。
2. `Server.mu sync.Mutex` 声明但从未使用（单 goroutine 顺序处理，长任务会阻塞 ping）。
3. README 宣称支持 `${VAR:-default}` 语法，实现正则不支持。
4. AGENTS.md 仍写「main.go 用显式 switch」，与重构后代码不符（文档漂移）。
5. `truncate` 按字节切片，中文错误信息会切出乱码。
