# MCP 2026-07-28 规范跟进评估

> 评估日期：2026-08-04  ｜  评估对象：llm-eyes-mcp 项目  ｜  规范版本：2026-07-28

## 一、结论速览

**建议：不必立刻跟进，但应纳入 Q3-Q4 路线图，优先级中等。**

核心理由：
1. 本项目（STDIO + 无状态 + 自实现协议层）与新规范"无状态核心"方向天然契合，**无技术债务压力**。
2. 项目**未触及任何被废弃功能**（roots / sampling / logging / HTTP+SSE / Tasks）。
3. 享有 **12 个月正式废弃窗口期**，时间充裕。
4. 但当前声明协议版本为 `2024-11-05`（已近两年），过于陈旧，建议借此机会直接跳到 `2026-07-28`，避免多次迁移。

## 三、本项目影响评估

本项目关键特征：
- **自实现协议层**（`internal/mcp/`），非依赖官方 SDK —— 迁移成本需自行承担，无 SDK 升级红利
- **STDIO + NDJSON 传输**，无 HTTP/SSE
- **无协议层 session**，跨调用状态用 `image_id` 显式句柄（已符合新规范推荐模式）
- **仅声明 `tools` capability**，未实现 resources / prompts / sampling / roots / elicitation / logging / subscribe / tasks

| 新规范变动 | 本项目是否受影响 | 说明 |
|------------|------------------|------|
| 移除 `Mcp-Session-Id` / 协议层 Session | ❌ 不受影响 | 本就无 session |
| 移除 `initialize` / `initialized` 握手 | ✅ 受影响 | 已实现，需移除 |
| 新增 `server/discover` RPC（MUST 实现） | ✅ 受影响 | 未实现，需新增 |
| `_meta` 逐请求携带版本 / 能力 / clientInfo | ✅ 受影响 | 当前靠握手协商 |
| 所有 result 增加 `resultType` 字段 | ✅ 受影响 | 需补字段 |
| 废弃 Roots / Sampling / Logging | ❌ 不受影响 | 均未实现 |
| `resources/subscribe` → `subscriptions/listen` | ❌ 不受影响 | 未实现 |
| Tasks 移至扩展 | ❌ 不受影响 | 未实现 |
| 废弃 HTTP+SSE | ❌ 不受影响 | 仅 STDIO |
| MRTR 替代服务端主动请求 | ❌ 不受影响 | 无主动请求 |
| `Mcp-Method` / `Mcp-Name` HTTP 头 | ❌ 不受影响 | STDIO 不涉及 |
| `tools/list` 结果可缓存（`ttlMs`） | ⚪ 可选增强 | 非强制 |

**核心判断**：本项目因 STDIO + 无状态架构，与"无状态核心"方向天然契合，**主要迁移点集中在握手层改造**，废弃类功能均未触及。

## 五、建议路线

```
2026-08 ──── 2026-09 ──── 2026-10 ──── 2026-11 ──── 2026-12 ──── ... ──── 2027-07
   │            │            │            │                        │
   │            │            │            │                        └─ 废弃窗口截止
   │            │            │            │
   │            │            │            └─ 完成迁移并发布新版本
   │            │            └─ 非生产环境验证
   │            └─ 启动迁移开发（分支并行）
   └─ 现状评估（本次）+ 排期决策
```

**关键建议**：
1. **不必抢首班车**：本项目无生产规模部署压力，可观察生态 1-2 个月稳定期再动手。
2. **直接跳到 2026-07-28**：避免先升 2025-11-25 再升一次的重复劳动。
3. **不必做双栈**：本项目客户端侧可控（自实现 + STDIO），单一新版本即可，无需双栈过渡。
4. **注意幂等性**：虽然本项目已是显式句柄模式，但无状态后客户端重试可能变频繁，确认 `image_id` 解析的幂等性。
5. **保留 `server/discover` 的 STDIO 兼容探测能力**：新规范要求 MUST 实现，本项目虽是 STDIO 也需实现。

## 六、不跟进的风险与跟进的风险对比

| 不立刻跟进的风险 | 立刻跟进的风险 |
|------------------|----------------|
| 协议版本陈旧（已是 2024-11-05） | 新规范发布仅 1 周，可能有 errata |
| 长期看与生态主流脱节 | 自实现协议层无 SDK 兜底，需自行验证细节 |
| 部分新客户端可能逐步放弃旧握手 | 投入产出比暂时不高（本项目无规模化痛点） |

**综合判断**：不立刻跟进的风险可控（12 个月窗口 + STDIO 兼容性好），立刻跟进的收益有限（无规模化痛点驱动）。建议**观察 1-2 个月后启动**，既避开新规范可能的 errata 期，又能在窗口期内从容完成。
